# Как помочь с переводом

Спасибо, что хотите сделать DSH понятнее на вашем языке. Пакет устроен так, что
каждый язык — это отдельная папка `locales/<код>/`, и языки не мешают друг другу.

## Быстрый старт для нового языка

```bash
git clone https://github.com/<ник>/dsh_languages && cd dsh_languages
node tools/new-locale.mjs de "Deutsch"   # создаст locales/de/ и запись в locales.json
```

Скрипт копирует английские строки как заготовку, чтобы сборка работала сразу.
Дальше переводите значения в `locales/de/*.json` — по файлу на namespace.
Проверка и сборка:

```bash
npm run check   # валидирует ключи/плейсхолдеры и пересобирает lib/client.js
```

Коммитьте `locales.json`, `locales/de/` и `lib/client.js`. В PR укажите язык и
себя как сопровождающего — можно вести его дальше самостоятельно.

## Файлы

- `locales/en/<namespace>.json` — английские строки, извлечённые из приложения.
  **Не редактируйте вручную**: обновляются командой
  `node tools/extract.mjs "<путь к>/resources/app.asar"`.
- `locales/<код>/<namespace>.json` — перевод. Плоский объект «ключ → строка»,
  ключи и их порядок как в `en/`.
- `locales.json` — каталог языков (код и подпись на самом языке).
- `lib/client.js` — собранный бандл. Генерируется `npm run build`.

## Правила перевода

1. **Плейсхолдеры** (`{name}`, `{count}`, `{value}`) переносите дословно; порядок
   слов можно менять по правилам вашего языка.
2. **Не переводите**: `DeepSeek`, `DSH`, `GitHub`, `MCP`, `JSON`, `API`, `HTTP`,
   названия моделей, пути и имена файлов, кодовые идентификаторы, сочетания клавиш,
   имена продуктов (Cursor, VS Code, PDF).
3. **Стиль**: кратко и нейтрально; кнопки — глагол в форме действия
   («Сохранить» / «Save» / «Speichern»), заголовки — с заглавной, короткие
   подписи — без точки в конце.
4. **Типографика**: сохраняйте `…`, `—`, `·`, обрамляющие пробелы и регистр первой
   буквы; кавычки — типографские вашего языка.
5. **Плюрализация**: ICU-форм в DSH нет, поэтому строки с `{count}` формулируйте
   нейтрально («Файлов: {count}», «Noch {count}»), избегая форм, зависящих от числа.
6. **Машинный перевод допустим** как черновик, но перед PR пройдитесь по строкам
   вручную: термины, падежи и длинные подписи в интерфейсе — главные источники
   ошибок.

## Глоссарий

Единые термины — залог непротиворечивого интерфейса. Для русского:

| English | Русский |
|---|---|
| agent / subagent | агент / субагент |
| session | сессия |
| workspace | рабочая область |
| turn / step | ход / шаг |
| tool / skill | инструмент / навык |
| plugin / preset / profile | плагин / пресет / профиль |
| permission / approval | разрешение / подтверждение |
| sandbox | песочница |
| job (background) | задача |
| goal / plan | цель / план |
| schedule | расписание |
| attachment / deliverable | вложение / результат |
| compaction | сжатие контекста |
| sidebar | боковая панель |
| shortcut | сочетание клавиш |

Для нового языка создайте такой же список в PR (или в `locales/<код>/GLOSSARY.md`) —
это помогает и переводчикам, и ревьюерам.

## Проверка

```bash
npm run check
```

Сборка падает, если:

- для языка нет файла перевода или в нём не хватает/лишние ключи;
- набор `{плейсхолдеров}` не совпадает с английским;
- значение пустое, хотя английское — нет.

CI дополнительно проверяет, что закоммиченный `lib/client.js` соответствует
`locales/` и `locales.json` (иначе `npm run build` даст дифф).

## Чужой язык без форка

Если не хотите отдавать перевод в общий пакет, выпустите собственный
плагин-язык: пакет с `dsh.client`, который вызывает
`ctx.locale.addLanguage({ id, label, fallback: 'en' })` и
`ctx.locale.register(ns, id, dict)` для каждого namespace. Этот репозиторий —
готовый шаблон: скопируйте `lib/client.js` и замените язык. DSH подхватит оба
плагина одновременно, а пользователь выберет язык в настройках.
